## 📋 Objetivo de la Práctica

El propósito de someter un servidor a pruebas de estrés controladas es comprobar la **reactividad y precisión** de la pila de monitorización. Generaremos sobrecargas sintéticas de **CPU**, **memoria RAM** y **operaciones de entrada/salida (I/O) en disco**, observando cómo Prometheus registra los picos en sus series temporales y cómo Grafana actualiza los gráficos en tiempo real.

---

## 🛠️ Herramientas de Estrés: `stress` y `stress-ng`

Instalamos ambas utilidades en la máquina a someter a carga:

```bash
sudo apt update
sudo apt install -y stress stress-ng
```

---

## 1. Prueba 1: Estrés de CPU al 100%

### Comando de ejecución:
```bash
# Somete a estrés 4 núcleos de CPU durante 60 segundos
stress --cpu 4 --timeout 60s
```

- **`--cpu 4`**: Lanza 4 procesos concurrentes que ejecutan cálculos continuos de raíces cuadradas (`sqrt()`) para saturar los núcleos de procesamiento.
- **`--timeout 60s`**: Detiene automáticamente la prueba transcurrido 1 minuto para evitar bloqueos del sistema.

### 🔍 Detección en Prometheus (PromQL):
En la pestaña *Graph* de Prometheus o en Grafana, ejecuta la siguiente consulta:

```promql
100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[30s])) * 100)
```

### 📈 Comportamiento en Grafana:
- El gráfico de uso de CPU pasará de un estado habitual en reposo ($1\% - 5\%$) a una línea vertical que alcanza el **$100\%$**.
- La métrica de carga media a 1 minuto (`node_load1`) comenzará a subir por encima del número de núcleos disponibles.

---

## 2. Prueba 2: Estrés de Memoria RAM

### Comando de ejecución:
```bash
# Asigna y libera continuamente 2 GB de memoria RAM durante 60 segundos
stress --vm 2 --vm-bytes 1G --timeout 60s
```

- **`--vm 2`**: Inicia 2 trabajadores dedicados a la gestión de memoria virtual.
- **`--vm-bytes 1G`**: Cada trabajador asigna $1\text{ GB}$ de memoria mediante llamadas `malloc()` y escribe en ella continuamente.

### 🔍 Detección en Prometheus (PromQL):
```promql
# Memoria RAM ocupada en Megabytes
(node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes) / 1024 / 1024
```

### 📈 Comportamiento en Grafana:
- La gráfica de **Memoria Disponible** (*Available Memory*) experimenta una caída abrupta de $2\text{ GB}$.
- Si el servidor tiene menos RAM física de la solicitada, se observa en tiempo real cómo el kernel recurre a la partición de intercambio (**Swap In / Swap Out**).

---

## 3. Prueba 3: Estrés de Entrada/Salida en Disco (I/O)

### Comando de ejecución:
```bash
# Genera operaciones masivas de sincronización de disco (sync) durante 60 segundos
stress --io 4 --hdd 2 --timeout 60s
```

- **`--io 4`**: Lanza 4 procesos ejecutando llamadas continuas a `sync()`.
- **`--hdd 2`**: Lanza 2 trabajadores escribiendo y leyendo bloques masivos en disco con la llamada `write()`.

### 🔍 Detección en Prometheus (PromQL):
```promql
# Tasa de escritura en disco en Megabytes por segundo
rate(node_disk_written_bytes_total[1m]) / 1024 / 1024
```

### 📈 Comportamiento en Grafana:
- El panel de **Disk IOPS** y **Disk Throughput** muestra un disparo inmediato en la tasa de transferencia ($MB/s$).
- La métrica de latencia o tiempo de espera de disco (`r_await` / `w_await`) aumenta significativamente.

---

## 4. Prueba 4: Estrés Masivo Combinado con `stress-ng`

Para simular una situación extrema de degradación de servicio en un servidor de producción:

```bash
stress-ng --cpu 2 --vm 1 --vm-bytes 512M --hdd 1 --timeout 45s --metrics-brief
```

La opción `--metrics-brief` genera un informe estadístico resumido al finalizar la prueba:
```text
stress-ng: info:  [21540] dispatching processes: 2 cpu, 1 vm, 1 hdd
stress-ng: info:  [21540] successful run completed in 45.02s
stress-ng: info:  [21540] stressor       bogo ops real time  usr time  sys time
stress-ng: info:  [21540] cpu               48201     45.00     89.12      0.15
stress-ng: info:  [21540] vm               124050     45.01     12.30     32.40
stress-ng: info:  [21540] hdd               23100     45.01      0.80     28.10
```

## 5. Cuadro Comparativo de Métricas Monitorizadas

| Tipo de Estrés | Métrica Clave en Prometheus | Umbral de Alerta Típico |
| :--- | :--- | :---: |
| **CPU** | `node_cpu_seconds_total` / `node_load1` | $> 85\%$ durante 2 min |
| **Memoria** | `node_memory_MemAvailable_bytes` | $< 10\%$ de la RAM total |
| **Disco I/O** | `node_disk_io_time_seconds_total` | Utilización disco $> 95\%$ |
| **Filesystem** | `node_filesystem_free_bytes` | Espacio libre $< 15\%$ |

> [!TIP]
> Durante estas pruebas, reduce temporalmente el `scrape_interval` de tu job en `prometheus.yml` a `5s` para apreciar con mayor granularidad la curva de aceleración y enfriamiento de los recursos del sistema.
