## 📋 Introducción

Un **Data Source** (origen de datos) es la conexión que permite a Grafana consultar un backend de almacenamiento. Para que Grafana pueda renderizar gráficos con las métricas del sistema, es necesario vincularlo con la API HTTP de Prometheus.

En esta unidad configuraremos Prometheus como Data Source predeterminado tanto desde la **interfaz gráfica** como mediante **aprovisionamiento declarativo YAML** (*Infrastructure as Code*).

---

## 1. Configuración interactiva desde la Interfaz Web

### Paso 1: Acceder al menú de Data Sources
1. Inicia sesión en Grafana (`http://localhost:3000`).
2. En el menú lateral izquierdo, haz clic en **Connections** $\rightarrow$ **Data sources** (o navega al icono de engranaje **Configuration** $\rightarrow$ **Data Sources** según la versión de Grafana).
3. Haz clic en el botón azul **Add data source**.

---

### Paso 2: Seleccionar el conector de Prometheus
1. En la lista de orígenes soportados, selecciona **Prometheus** (suele aparecer destacado en la categoría *Time series databases*).

---

### Paso 3: Rellenar los parámetros de conexión

Configura los campos obligatorios:

| Campo | Valor Recomendado | Explicación |
| :--- | :--- | :--- |
| **Name** | `Prometheus` | Nombre identificador del Data Source en Grafana. |
| **Default** | Activado (`Toggle On`) | Establece Prometheus como origen predeterminado para nuevos paneles. |
| **Prometheus server URL** | `http://localhost:9090` | Dirección y puerto donde escucha la API de Prometheus (si están en hosts distintos, indica `http://<IP_PROMETHEUS>:9090`). |
| **HTTP Method** | `POST` | Método de envío de peticiones (el método `POST` soporta queries más largas y complejas sin desbordar cabeceras). |
| **Scrape interval** | `15s` | Debe coincidir con el `scrape_interval` configurado en `prometheus.yml`. |

> [!WARNING]
> No utilices `localhost` si Grafana se está ejecutando dentro de un contenedor Docker aislado de la red del host; en ese caso debes usar la IP de la interfaz puente o el nombre del servicio en la red de Docker.

---

### Paso 4: Validar la conexión (*Save & Test*)
1. Desplázate hasta la parte inferior de la página.
2. Haz clic en el botón verde **Save & test**.
3. Deberá aparecer un mensaje de confirmación con fondo verde:

```text
✅ Successfully queried the Prometheus API.
```

Si aparece un error rojo de conexión:
- Comprueba que Prometheus sigue en ejecución (`systemctl status prometheus`).
- Verifica que el puerto 9090 no esté bloqueado por el firewall `ufw` (`sudo ufw allow 9090/tcp`).

---

## 2. Verificación de Métricas con la herramienta *Explore*

Grafana incluye una consola interactiva llamada **Explore** diseñada para depurar y probar consultas PromQL sin necesidad de crear un dashboard definitivo:

1. En el menú lateral izquierdo, haz clic en **Explore** (icono de brújula 🧭).
2. Asegúrate de que el desplegable superior tenga seleccionado el origen **Prometheus**.
3. En el campo de consulta (modo *Code* o *Builder*), introduce:
   ```promql
   up
   ```
4. Haz clic en **Run query** (arriba a la derecha).
5. Observarás una gráfica de líneas y una tabla inferior mostrando las instancias scrapeadas con valor `1` (operativa).

---

## 3. Método DevOps: Aprovisionamiento Automático con YAML

En entornos automatizados (Ansible, Puppet o Docker), Grafana permite autoconfigurar sus Data Sources al arrancar mediante archivos YAML en `/etc/grafana/provisioning/datasources/`:

```bash
sudo nano /etc/grafana/provisioning/datasources/prometheus.yaml
```

Contenido del archivo:

```yaml
apiVersion: 1

datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://localhost:9090
    isDefault: true
    jsonData:
      httpMethod: POST
      timeInterval: 15s
    editable: true
```

Tras guardar el archivo, reinicia Grafana:
```bash
sudo systemctl restart grafana-server
```
El Data Source aparecerá creado y listo para usar sin requerir ninguna acción manual en la interfaz web.
